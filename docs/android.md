# Android

Power Log uses the same React Native screens, preferences, measurement catalog, chart interactions and typed service interfaces as iPhone. Both phones use the shared bottom tab bar, sheets, switches, chart cards, Reanimated gestures and haptic action service. Native chart backends draw the same scene and exact-marker contract. Android 9+ supplies its own Kotlin implementation of the existing `CycBridge` boundary: one validating parser turns every incoming bridge map into typed values before any Bluetooth, permission, Health Connect or storage effect (a malformed or wrong-typed value is rejected, never defaulted), and one typed ride snapshot serves both method results and events. Android watch recording is excluded; Health Connect is a phone export destination, not a watch connection. [Measurements](measurements.md) define distance, source and missing-data rules, and [chart queries and rendering](architecture.md#chart-queries-and-rendering) define the display contract; this page records only what Android does differently or additionally.

## Recording

A native foreground service owns Bluetooth polling, GPS, writes and notification controls. Switching apps, locking the screen or dismissing the activity does not depend on a JavaScript timer. Pause, Resume and Finish work from the notification, which is rebuilt only when the ride, its phase or its timer anchor changes; the system chronometer advances it between those transitions. Ride and live-monitor starts capture UTC and monotonic time back to back before their storage transaction; every stored start timestamp and the elapsed-time origin use that same reading, including the ride's active-timer origin. The engine publishes the new ride only after creation commits. The observation count is computed once, when the ride is sealed. Each checkpoint stores UTC with its elapsed and active time, lifecycle rows keep their original UTC (also in the ZIP), and an interrupted ride is sealed at its last retained checkpoint. Android's Force stop, system termination or a device reboot interrupts capture; reopening preserves the committed prefix as an interrupted ride instead of claiming unseen time was recorded.

BLE operations are serialized: connect, discover UART, subscribe, identify, then poll. Only identity and selective telemetry requests are permitted. Polling follows the selected cadence without adding storage time to each interval; it keeps one request outstanding and resets its schedule after a long stall. Requests have deadlines; a recording retries its selected bike with capped backoff. Disconnects retain real gaps. The shared UI's six-second visual hold does not create samples. Replacing the selected bike requires finishing the ride.

Recorded elapsed time is the capture timeline measured with a monotonic clock; original UTC stays as captured through wall-clock changes. Android recovery seals the retained prefix and never adds unobserved downtime to elapsed. Health Connect places observations at original UTC and omits those outside the retained workout UTC interval, while FIT places records at start plus elapsed in one-second bins. Their placement can therefore differ after a clock change; Health/FIT equality is not guaranteed. Apple recovery can resume capture with downtime compressed out of elapsed, while raw Apple Health samples keep UTC-derived placement and remain retained even when they cannot be aligned; see the shared [time-domain limits](measurements.md#evidence-and-limits).

Nearby devices and, when selected, precise location are requested from a visible activity. Location uses a foreground service; background-location permission is unnecessary. Notifications are requested for lock-screen controls. See Android's [BLE background guidance](https://developer.android.com/develop/connectivity/bluetooth/ble/background) and [foreground-service types](https://developer.android.com/develop/background-work/services/fgs/service-types).

SQLite WAL stores typed original observations, lifecycle events, indexed ride metadata and distance intervals, with persistent 16-second chart/statistics checkpoints. Capture commits small batches; history lists metadata only. Chart reads run on a separate worker, retain first/minimum/maximum/last originals per continuous run within each bucket, and preserve original IDs for exact inspection. Inspection selects an exact observation or the nearest endpoint of a containing continuous span, choosing the earlier point on ties. Completed rides never borrow outside the observed extent; running and paused rides may expose a trailing original only within the metric's display gap. Live readouts come from a process-local record of each metric's newest committed observation and its acquisition time, so a live read is one indexed lookup; without that record (for example after a restart) a live metric shows no reading. Distance inspection requires a supported distance interval. Telemetry rendering stays continuous across reconnects shorter than six seconds; course geometry breaks at the north wrap. Metadata reads retry a bounded number of times if capture changes their revision; continued contention defers the read and retains the current chart. Canvas rasterizes geometry off the UI thread; gestures transform the accepted image.

Auto distance chooses phone GPS outdoors, otherwise normalized controller speed; indoor Auto excludes GPS. Explicit GPS selection remains available when recorded. Distance treats a GPS interval as stationary only when both speeds are below 0.5 m/s and neither fix reports an invalid (negative or non-finite) speed accuracy, and reports partial coverage when more than 0.001 seconds of active time is uncovered. Pauses, invalid fixes and connection epochs stop distance integration; continuity comes from the persisted observation fields (segment, active flag, epoch), and each original commits together with its distance derivation, so replaying a ride's originals reproduces the same intervals. Summary and range statistics use active observations only; paused originals remain plotted, inspectable and included in the ride-data ZIP. Telemetry integration requires adjacent active observations in the same segment and connection epoch, at most 2.5 seconds apart. Display holds never contribute to statistics or distance.

Android exports the same FIT and ride-data ZIP as iPhone, built by the shared exporter described in [storage](storage.md#exports). A ride with GPS anchors its FIT clock to GPS time. `ExportSource.kt` reads each stream with two bounded index seeks on `(ride, kind, time, id)` (lifecycle on `(ride, time, id)`) and holds the ride's deletion protection while the export is open; any change to the ride's data fails the export. GPS altitude is stored as WGS84 ellipsoid height; the ZIP keeps that pair and adds the mean-sea-level pair from `AltitudeConverter` on Android 14 and later, which FIT also uses. The committed file in `files/exports/<uuid>/` is shared directly through Android's private FileProvider, which grants access to that one file; no external-storage permission is required. Optional Health Connect saving (frozen off at Start when Health Connect is unavailable) writes completed rides and measurements in bounded batches with stable record IDs and original UTC sample times. Samples and subrecords outside the workout, or with invalid intervals, are omitted rather than clamped, and the ride records how many items were written and omitted, and why. The outcome is `saved`, `notSaved` (retryable, offers repair; also used when the recording was interrupted before saving) or `unavailable` (permanent, for example when the clock put the end before the start); Power Log retains the local ride in every case. Finish records the pending save in the same transaction that seals the ride, so a save interrupted by process death resumes on the next launch. A Health Connect route preview is limited to 5,000 fixes; ZIP retains all original fixes. Health Connect access is write-only. Starting with Health saving on and saving a completed ride require an available provider and exercise-session write access; local recording with Health off needs neither. The permission request includes exercise session, power, cadence and distance even with GPS off, plus speed and exercise route when GPS is selected. Missing requested access offers Set up permissions, which requests the full selected set through Health Connect. This includes speed and route access when GPS is enabled after setup without GPS. The setup card does not block Start, and Start does not reopen the Health request. Each provider write rechecks grants and includes only authorized types; a denied type counts as an omission only when eligible recorded data exists, with one reason per type. A denied route leaves the session without a route. A security failure retries the batch once after dropping newly denied types; other failures remain `notSaved`. Power accepts 0–5,000 W and cadence 0–300 rpm; values outside those ranges are omitted. Health Connect uses the same `WRITE_EXERCISE` grant for sessions and cycling cadence, so cadence cannot be denied independently ([data-type permissions](https://developer.android.com/health-and-fitness/health-connect/data-types)). See [Health Connect data writing](https://developer.android.com/health-and-fitness/health-connect/write-data).

## Build and test

Install Node 24, JDK 17 and Android Studio's SDK/platform tools. Set `JAVA_HOME` and `ANDROID_HOME` if they are not detected. Generated `android/` is disposable; maintain code in `modules/cyc-bridge/android/`, app configuration and the config plugin.

```sh
npm ci
npm run build:android -- --preview
npm run test:android
# Start an Android emulator before this stress test:
npm run test:android -- --emulator
```

The preview is a release-mode, offline-capable APK signed with the public development key, under the separate `app.powerlog.mobile.preview` package. Output: `artifacts/builds/android/power-log-preview.apk`. `--arch=arm64-v8a` limits a local build to one architecture. Never use the development key for public releases.

The native tests cover the shared distance vectors, insertion-order replay equivalence, wire fixtures, transaction rollback, interrupted recovery, gap-aware distance, bounded plots, exact inspection, export pages, sinks and sharing, Health Connect record mapping and marker stability. `RideFixtureTest` creates only synthetic data for emulator screenshots. The emulator stress test retains eight hours of 8 Hz originals and measures indexed queries. Emulator results do **not** validate real Bluetooth, controller reconnection, radio power consumption or vendor background restrictions. Physical acceptance must include a locked-screen ride across several controller reconnects and compare original timestamps after finishing.

FIT files are decoded independently by the shared exporter's tests ([testing](testing.md)). Compare Android UI screenshots with the iPhone references in `artifacts/app-store/screenshots/iphone/`; test populated and empty cards, cursor selection, sheets and bottom tabs. Exercise permission prompts, a background/screen-off GPS ride, notification controls and FIT/ZIP sharing in the installed release-mode APK as well as the native tests.

## GitHub releases

Releases are built and published from the maintainer's Mac: `npm run release:android -- <version>`. It needs `main` pushed and checked out without local changes, `package.json` and its lockfile at that version, and the signing variables `POWER_LOG_ANDROID_KEYSTORE` (path to the keystore), `POWER_LOG_ANDROID_STORE_PASSWORD`, `POWER_LOG_ANDROID_KEY_ALIAS` and `POWER_LOG_ANDROID_KEY_PASSWORD`. It runs `npm run verify`, builds the signed APK with version code major × 10000 + minor × 100 + patch, downloads the latest release's APK and stops unless both carry the same signing certificate, then tags the commit, pushes the tag and creates the GitHub release with `power-log.apk` and `SHA256SUMS.txt`. Existing release assets are never replaced.

Keep the signing key and a secure backup outside the repository. Updates require the same key. The build fails if release signing is missing; it never substitutes the public debug key. See [Android app signing](https://developer.android.com/studio/publish/app-signing).
